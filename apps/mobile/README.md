# @taskbeavo/mobile

The Expo app for iOS and Android, with Expo Router. It runs in a **development build** (`expo-dev-client`); Expo Go isn't supported. The `ios/` and `android/` folders are generated by `expo prebuild` and aren't committed.

## Run it

```bash
pnpm --filter @taskbeavo/mobile start      # Metro for the dev client (expo start --dev-client)
```

Then open the TaskBeavo (Dev) app on a simulator, emulator or device that has a development build installed.

To build a development build locally instead of on EAS (needs Xcode, or the Android SDK):

```bash
pnpm --filter @taskbeavo/mobile ios        # expo run:ios
pnpm --filter @taskbeavo/mobile android    # expo run:android
```

`APP_ENV` picks the variant in `app.config.ts`; each EAS profile sets it.

## Links

`https://taskbeavo.com` and `www.` links to tasks, bookings ("Release payment", no access) and conversations open the app: `ios.associatedDomains` and a verified Android intent filter come from `@taskbeavo/app-links` (`packages/app-links`), which the web app reads too, and the web app serves the association files (`apps/web`, "App links"). `app/+native-intent.tsx` maps every incoming URL through `src/links/routes.ts`: the web's locale prefix and any query string are dropped, unknown links open the home screen. Push taps don't go through it yet: the tap handler that comes with push registration must pass `data.route` through `appPathFromLink` as well, including `getLastNotificationResponseAsync` on a cold start. Only the email link opens the release screen today. A link only opens a screen; anything that moves money still needs the user's tap and the server's checks. These are native settings, so they reach a device only with a new build.

```bash
npx uri-scheme open "taskbeavo://bookings/123/release" --ios          # any build, no association needed
npx uri-scheme open "https://taskbeavo.com/de/bookings/123/release" --android
xcrun simctl openurl booted "https://taskbeavo.com/tasks/42"
adb shell pm get-app-links com.taskbeavo.app                          # Android verification state
```

## EAS

Profiles in `eas.json`: `development` (dev client, internal), `development-simulator` (the same, built for the iOS simulator), `preview` (internal) and `production` (store, build number auto-incremented by EAS).

First-time setup, run once by a project owner:

1. `cd apps/mobile && eas login`
2. `eas init` — done. The Expo project is `taskbeavo` on the owner's Expo account, project ID `3ea41387-caed-438b-a103-a54f006a6ff9`, set as `easProjectId` in `app.config.ts` (EAS CLI can't write to a dynamic config).

Development builds that Expo Orbit can install:

```bash
cd apps/mobile
eas build --profile development-simulator --platform ios   # iOS simulator (.app)
eas build --profile development --platform android         # Android emulator or device (.apk)
eas build --profile development --platform ios             # physical iPhone; register it first with `eas device:create`
```

Open Expo Orbit from the macOS menu bar, pick the build from the EAS list, and choose the simulator, emulator or device. Release builds, store submissions and updates are described in the `expo-release` skill.

## Errors and tracing

Sentry (EU) gets JavaScript errors and native crashes only: no Session Replay, screenshots, view hierarchy or personal data (`src/sentry/options.ts`). JavaScript events go through `@taskbeavo/graphql`'s scrubber; native iOS and Android crashes, ANRs and native breadcrumbs don't, and rely on `sendDefaultPii: false` alone, so native code must never log user data. The Apollo `telemetryLink` sends a W3C `traceparent` with every operation, so the backend's spans in Honeycomb share the app action's trace ID, and a failed request reaches Sentry tagged with `graphql.operation.name` and `trace_id`.

| EAS environment variable       | Use                                                                                                                                                                    |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `EXPO_PUBLIC_SENTRY_DSN`       | Sentry DSN in the EU region (`*.ingest.de.sentry.io`); without it, or with any other region, Sentry stays off. Per environment (development, preview, production).     |
| `SENTRY_AUTH_TOKEN`            | Secret, preview and production: org token for the source map and debug file upload. Preview and production builds fail without it; development builds skip the upload. |
| `SENTRY_ORG`, `SENTRY_PROJECT` | The Sentry organisation and the mobile project's slugs.                                                                                                                |

EAS Build uploads source maps (Metro adds debug IDs through `metro.config.js`) and iOS/Android debug files. An EAS Update doesn't: after `eas update`, run `npx sentry-expo-upload-sourcemaps dist` with the same variables set.
